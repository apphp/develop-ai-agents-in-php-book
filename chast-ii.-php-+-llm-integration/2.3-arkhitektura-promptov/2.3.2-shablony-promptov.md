# 2.3.2 Шаблоны промптов

Большинство промптов в промышленных AI-системах содержат не только статический текст, но и данные, которые меняются для каждого запроса. Такие данные подставляются в промпт во время выполнения программы.

Например, система анализа обращений клиентов может использовать следующий шаблон:

```
Проанализируй обращение клиента.

Текст:
{{message}}

Верни JSON:
{
  "sentiment": "...",
  "urgency": "..."
}
```

В данном случае `{{message}}` является переменной, значение которой будет заменено реальным текстом обращения клиента. Такой подход называется использованием шаблона промпта (prompt template).

Во время работы приложения система загружает шаблон и подставляет в него необходимые данные.

Пример на PHP:

```php
$template = file_get_contents(
    'prompts/sentiment_analysis.txt'
);

$prompt = str_replace('{{message}}', $message, $template);
```

После подстановки переменной формируется готовый промпт, который отправляется языковой модели.

По своей идее такой механизм очень похож на работу шаблонизаторов Blade, Twig или Mustache, где в заранее подготовленный шаблон подставляются динамические данные.

В реальных проектах количество параметров обычно значительно больше. Помимо текста обращения могут использоваться имя клиента, история предыдущих запросов, язык общения, название продукта и данные из внутренней базы знаний.

Например:

```
{{customer_name}}
{{ticket_history}}
{{language}}
{{product_name}}
{{knowledge_base}}
```

В результате один и тот же шаблон может использоваться для обработки тысяч различных запросов, при этом содержимое промпта будет адаптироваться под конкретную ситуацию.

По мере роста AI-системы управление шаблонами становится всё более важной задачей. Увеличивается количество переменных, усложняется логика формирования запросов, появляются разные версии шаблонов для различных сценариев работы. Поэтому шаблоны обычно хранятся отдельно от программного кода, проходят версионирование и сопровождаются так же тщательно, как и остальные компоненты системы.

Таким образом, шаблоны промптов позволяют отделить структуру запроса к модели от конкретных данных, которые используются при его выполнении. Это делает систему более гибкой, упрощает сопровождение проекта и позволяет повторно использовать одни и те же промпты в различных сценариях.
