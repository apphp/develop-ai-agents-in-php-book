# 2.3.1 Prompt как программный артефакт

Рассмотрим систему поддержки клиентов в рамках разрабатываемого SaaS-приложения.

Предположим, что AI должен выполнять несколько задач: определять тональность обращения клиента, классифицировать тип запроса, формировать краткое резюме обращения и генерировать рекомендации или ответы для оператора службы поддержки. Для каждой из этих задач обычно создаётся отдельный промпт, поскольку требования к входным данным и ожидаемому результату различаются.

На ранних этапах разработки количество промптов может быть небольшим, однако по мере развития проекта их число быстро увеличивается. Через несколько месяцев работы система может содержать десятки специализированных промптов для различных сценариев.

В результате в проекте появляются десятки, а иногда и сотни промптов.

Распространённой ошибкой является хранение текстов промптов непосредственно внутри PHP-кода.

Например:

```php
$response = $client->responses()->create([
    'model' => 'gpt-5',
    'input' => "
        Ты опытный агент поддержки.
        Проанализируй сообщение.
        Определи настроение клиента.
        Верни JSON...
    "
]);
```

На первых этапах такой подход может показаться удобным, однако со временем он создаёт серьёзные проблемы. Тексты промптов оказываются разбросаны по различным частям приложения, что затрудняет их поиск и сопровождение. Становится сложно отслеживать изменения, сравнивать версии промптов между собой, проводить тестирование и анализировать влияние отдельных изменений на качество ответов модели.

Поэтому на практике промпт рекомендуется рассматривать как самостоятельный артефакт проекта, аналогично конфигурационным файлам, шаблонам или исходному коду.

Для этого промпты обычно выносятся в отдельный каталог:

```
prompts/
├── sentiment_analysis.txt
├── ticket_summary.txt
├── reply_generation.txt
└── escalation_detection.txt
```

Такой подход позволяет централизованно управлять промптами, упрощает их редактирование и делает структуру проекта более понятной. Кроме того, отдельные файлы легче включать в систему контроля версий, сравнивать изменения между редакциями и использовать в автоматизированных тестах.

По мере роста AI-системы промпты начинают играть роль полноценного программного ресурса. Они требуют документирования, тестирования, версионирования и сопровождения так же, как и остальные компоненты приложения. Именно поэтому в современных AI-проектах промпт рассматривается не как строка текста внутри кода, а как отдельный элемент архитектуры системы.
