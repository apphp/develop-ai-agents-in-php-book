# 2.2.3 Typed AI responses и DTO

### Типизация ответов AI

Когда JSON-ответы от AI становятся стабильными и предсказуемыми, следующим шагом обычно становится их типизация. В PHP для этого часто используются объекты передачи данных (DTO — Data Transfer Object), которые позволяют представить результат работы модели в виде строго определённой структуры.

Например, результат анализа тональности текста можно описать следующим классом:

```php
final class SentimentAnalysisResult
{
    public function __construct(
        public readonly string $sentiment,
        public readonly float $urgency,
        public readonly string $summary,
    ) {}
}
```

После этого ответ AI перестаёт быть обычным набором данных и превращается в типизированный объект, с которым приложение может работать так же, как и с любыми другими объектами предметной области.

Преобразование JSON-ответа в DTO может выглядеть следующим образом:

```php
$data = json_decode($response, true);

$result = new SentimentAnalysisResult(
    sentiment: $data['sentiment'] ?? '',
    urgency: $data['urgency'] ?? '',
    summary: $data['summary'] ?? '',
);
```

Такой подход значительно повышает надёжность AI-системы. Вместо обработки неструктурированного текста приложение начинает работать с типами данных, контрактами взаимодействия, ограничениями целостности данных и правилами валидации.

### DTO как пограничный слой

DTO особенно важны при разработке AI-систем, поскольку результатам языковой модели нельзя доверять без дополнительной проверки. Модель может вернуть неполные данные, неверный формат или неожиданные значения. DTO создают чёткую границу (boundary layer) между вероятностной частью системы, где работает AI-модель, и детерминированной бизнес-логикой приложения, которая требует строгих правил и предсказуемого поведения.

С архитектурной точки зрения этот процесс можно представить следующим образом:

```
AI-модель → Валидация → DTO → Бизнес-логика
```

Сначала приложение получает ответ от модели, затем проверяет его структуру и корректность, после чего преобразует данные в DTO. Только после этого информация передаётся в бизнес-логику системы.

### Почему ассоциативных массивов недостаточно

На начальных этапах разработки многие PHP-разработчики работают с ответами AI через ассоциативные массивы:

```php
$data['urgency']
```

Однако по мере роста системы такой подход становится всё менее удобным и безопасным. В промышленных AI-решениях появляются версии схем данных, повторные запросы при ошибках, резервные модели, механизмы наблюдаемости, оценка уверенности модели в ответе, маршрутизация запросов и оркестрация нескольких AI-компонентов. В таких условиях использование DTO позволяет сохранить читаемость кода, повысить надёжность системы и упростить её дальнейшее сопровождение и развитие.

DTO помогают удерживать систему под контролем.
