# 2.1.12 Failover между моделями

### Переключение между моделями при отказе

В рабочих системах редко используют только одну языковую модель. Если выбранная модель временно недоступна или возвращает ошибку, система может автоматически обратиться к другой модели.

Например, запросы могут последовательно направляться в разные сервисы:

**GPT → Claude → Ollama**

Такой подход называется переключением при отказе. Его цель – обеспечить непрерывную работу приложения даже при сбоях отдельных поставщиков моделей (failover).

Простейшая реализация на PHP может выглядеть следующим образом:

```php
foreach ($providers as $provider) {
    try {
        return $provider->generate($prompt);
    } catch (Throwable $e) {}
}
```

В этом примере система последовательно перебирает доступные сервисы. Если один из них возвращает ошибку, выполняется попытка обратиться к следующему.

Использование нескольких поставщиков моделей повышает устойчивость системы, уменьшает зависимость от одного сервиса и помогает сохранить работоспособность приложения во время сбоев или перегрузок.

### **Примеры работы с** failover

#### **Пример на PHP**

```php
foreach ($providers as $provider) {
    try {
        return $provider->generate($prompt);
    } catch (Throwable $e) {}
}
```

### **Пример в Laravel**

```php
app(AIService::class)->ask($prompt);
```

При этом логика выбора модели может быть скрыта внутри сервиса. Например, сервис может автоматически направлять запросы разным поставщикам в зависимости от их доступности, стоимости обработки или текущей нагрузки.
