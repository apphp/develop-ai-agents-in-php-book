# 2.1.9 Retries и exponential backoff

### Повторные попытки выполнения запроса

Интерфейсы больших языковых моделей (LLM API) не всегда работают стабильно. Запрос может завершиться ошибкой по нескольким причинам:

* превышено допустимое количество запросов
* возникли проблемы с сетью
* сервис испытывает высокую нагрузку

Поэтому при работе с такими сервисами рекомендуется использовать механизм повторных попыток (retries). Однако важно не отправлять новый запрос сразу после ошибки. Лучше постепенно увеличивать паузу между попытками. Такой подход называется экспоненциальным увеличением задержки (exponential backoff).

Задержка рассчитывается по формуле:

$$
delay = base × 2ⁿ
$$

где:

* $$base$$ – начальная задержка;
* $$n$$ – номер попытки.

Например, в PHP задержку можно задать так:

```php
sleep(pow(2, $attempt));
```

Такой подход позволяет снизить нагрузку на сервис и уменьшить вероятность повторных ошибок. Кроме того, он помогает избежать ситуации, когда большое количество клиентов одновременно начинает бесконтрольно повторять запросы после сбоя (retry storm).

### **Примеры работы с r**etries

#### **Пример реализации на PHP**

```php
function retry(callable $fn, int $max = 5) {
    for ($i = 0; $i < $max; $i++) {
        try {
            return $fn();
        } catch (Throwable $e) {
            sleep(pow(2, $i));
        }
    }

    throw new Exception('Превышено максимальное количество попыток');
}
```

#### **Использование вспомогательной функции Laravel**

```php
use Illuminate\Support\Facades\Http;

$response = retry(5, function () {
    return Http::get('https://api.openai.com/v1/models');
});
```
