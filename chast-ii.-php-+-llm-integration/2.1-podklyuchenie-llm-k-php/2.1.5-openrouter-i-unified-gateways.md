# 2.1.5 OpenRouter и unified gateways

OpenRouter предоставляет единый интерфейс для работы сразу с большим количеством языковых моделей.

### **Архитектура**

```
PHP → OpenRouter → несколько языковых моделей
```

Вместо прямого подключения к каждой модели по отдельности приложение работает через один общий сервис.

#### **Преимущества**

* единый интерфейс для всех моделей
* доступ к десяткам моделей
* простое переключение при сбоях
* гибкость при выборе модели под задачу

Такой подход упрощает разработку и позволяет быстрее менять поставщиков моделей без серьёзной переработки системы.

### **Пример для Laravel**

```php
$response = Http::withToken(env('OPENROUTER_API_KEY'))
    ->post('https://openrouter.ai/api/v1/chat/completions', [
        'model' => 'openai/gpt-4.1-mini',
        'messages' => [
            ['role' => 'user', 'content' => 'Explain transformers']
        ]
    ]);
```

В этом примере приложение отправляет запрос через OpenRouter к модели GPT-4.1 Mini и получает ответ через единый API.

### **Ещё один пример: выбор другой модели**

```php
$response = Http::withToken(env('OPENROUTER_API_KEY'))
    ->post('https://openrouter.ai/api/v1/chat/completions', [
        'model' => 'anthropic/claude-3.5-sonnet',
        'messages' => [
            ['role' => 'user', 'content' => 'Составь краткое резюме этого текста']
        ]
    ]);
```

В этом примере код остаётся почти таким же, но меняется модель. Это удобно, когда нужно быстро сравнить качество ответов разных поставщиков.
