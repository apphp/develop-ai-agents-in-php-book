# 2.1.7 Структурированные ответы

### Structured responses

По умолчанию языковая модель возвращает обычный текст, а не строгую структуру данных.

Но в реальных системах часто нужен не просто текстовый ответ, а данные в формате JSON:

```json
{
  "summary": "text",
  "score": 0.87
}
```

Например, система может ожидать краткое описание и числовую оценку. Эти данные потом нужно сохранить в базу, передать дальше или использовать в бизнес-логике.

### **Проблема**

Модель может вернуть ответ не в том виде, который ожидает приложение.

Например:

```
Sure! Here is JSON:
{ broken json
```

Для человека понятно, что модель пыталась вернуть JSON. Но для программы такой ответ бесполезен: его нельзя надёжно разобрать и использовать.

Поэтому в реальных приложениях используют структурированный вывод и обязательную проверку результата.

### **Решение: объект для данных**

В PHP можно описать отдельный объект - DTO, который будет хранить результат анализа:

```php
class AnalysisResult {
    public function __construct(
        public string $summary,
        public float $score
    ) {}
}
```

Такой объект явно показывает, какие данные ожидает система: текстовое описание и числовую оценку.

#### **Слой проверки в Laravel**

Перед созданием объекта нужно проверить, что ответ действительно содержит нужные поля:

```php
$data = $response->json();

abort_unless(isset($data['summary']), 500);
abort_unless(isset($data['score']), 500);

$result = new AnalysisResult(
    $data['summary'],
    $data['score']
);
```

Так приложение не доверяет ответу модели вслепую. Сначала оно проверяет структуру данных, и только потом использует результат дальше.

Это делает систему надёжнее: даже если модель вернёт неправильный формат, ошибка будет поймана на уровне приложения, а не приведёт к скрытым сбоям в бизнес-логике.
