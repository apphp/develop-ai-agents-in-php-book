# 2.1.6 Единый уровень абстракции AI

### Единый слой работы с AI

Без отдельного слоя для работы с искусственным интеллектом код быстро становится неаккуратным и сложным для поддержки.

Например, в проекте могут появиться такие проверки:

```php
if ($provider === 'openai') {}
if ($provider === 'anthropic') {}
if ($provider === 'ollama') {}
```

Сначала это кажется простым решением. Но со временем таких условий становится всё больше, логика размазывается по проекту, а замена одного поставщика моделей на другого превращается в проблему.

### Общий интерфейс

Лучше заранее описать единый интерфейс для всех поставщиков:

```php
interface AIProvider {
    public function generate(string $prompt): AIResponse;
}
```

Так приложение работает не с конкретным поставщиком, а с общим договором: любой провайдер должен уметь принять запрос и вернуть ответ.

#### **Сервис в Laravel**

```php
class AIService
{
    public function __construct(
        private AIProvider $provider
    ) {}

    public function ask(string $prompt): string
    {
        return $this->provider->generate($prompt)->text;
    }
}
```

Такой сервис скрывает детали работы с конкретной моделью. Остальная часть приложения просто вызывает метод `ask()` и не думает о том, используется OpenAI, Anthropic, Ollama или другой поставщик.

#### **Что это даёт**

Такой подход даёт:

* независимость от конкретного поставщика моделей
* возможность легко добавлять новых поставщиков
* централизованный контроль над запросами, ответами, ошибками и настройками

В результате код становится чище, а система – гибче и проще в развитии.
