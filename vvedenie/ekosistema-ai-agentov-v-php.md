# Экосистема AI-агентов в PHP

### Предистория

Первые годы развития генеративного ИИ большинство PHP-разработчиков работали на очень низком уровне. Типичное взаимодействие с моделью выглядело примерно так:

```php
$response = $client->chat()->create([
    'model' => 'gpt-5',
    'messages' => [
        [
            'role' => 'user',
            'content' => 'Проанализируй это сообщение клиента'
        ]
    ]
]);
```

Такой подход отлично подходит для первых экспериментов, но быстро становится неудобным в реальных проектах.

Практически любая серьезная AI-система требует значительно больше возможностей:

* работу с несколькими моделями одновременно
* автоматический выбор провайдера
* вызов инструментов (tools)
* память агента
* структурированный вывод;
* оркестрацию цепочек запросов
* трассировку и мониторинг
* управление контекстом

По мере роста популярности AI-разработки вокруг PHP начала формироваться полноценная экосистема библиотек, которые берут на себя большую часть инфраструктурной работы.

Сегодня экосистему PHP для разработки AI-агентов можно условно разделить на три уровня:

1. AI SDK
2. Agent Frameworks
3. Agent Platforms

Каждый следующий уровень абстрагирует разработчика от все большего количества инфраструктурных задач.

### Почему появились AI-фреймворки

Представим наш сквозной проект поддержки клиентов.

Система получает письмо:

> "Я уже три раза писал вам по поводу возврата денег. Никто не отвечает."

На первый взгляд задача проста:

1. Отправить текст в LLM
2. Получить ответ
3. Показать результат оператору

На практике появляется множество дополнительных задач:

* определить тональность сообщения
* оценить срочность
* найти похожие обращения
* получить данные клиента из CRM
* сформировать черновик ответа
* сохранить историю действий агента
* записать логи

Если каждую из этих операций реализовывать вручную, код быстро превращается в набор разрозненных интеграций.

Именно поэтому появились AI-фреймворки.

Их задача – поднять уровень абстракции выше обычного HTTP-клиента.

### Prism

Репозиторий: [https://github.com/prism-php/prism](https://github.com/prism-php/prism)

Статус: <mark style="color:green;">**активный**</mark>

Одним из наиболее популярных AI-пакетов в PHP-сообществе стал Prism. Он появился как попытка предоставить единый интерфейс для работы с различными AI-провайдерами.

Основная идея проста: PHP-код не должен зависеть от конкретной модели. Вместо этого приложение работает через единый API.

Условно говоря:

```php
Prism::text()
    ->using('openai', 'gpt-5')
    ->withPrompt('Привет')
    ->generate();
```

Завтра этот же код можно переключить на другую модель:

```php
Prism::text()
    ->using('anthropic', 'claude')
    ->withPrompt('Привет')
    ->generate();
```

Бизнес-логика останется неизменной.

#### Генерация текста

Простейший пример:

```php
use Prism\Prism\Prism;

$response = Prism::text()
    ->using('openai', 'gpt-5')
    ->withPrompt('Сделай краткое резюме письма клиента')
    ->generate();

echo $response->text;
```

В результате разработчик получает единый интерфейс независимо от используемого провайдера.

#### Structured Output

Prism поддерживает работу со структурированным выводом.&#x20;

Например, нам необходимо определить тональность письма. Мы можем описать ожидаемую структуру:

```php
class SentimentResult
{
    public string $sentiment;
    public int $score;
}
```

После чего попросить модель вернуть данные в этом формате.

Результат:

```json
{
  "sentiment": "negative",
  "score": 92
}
```

Это значительно надежнее, чем разбирать свободный текст.

#### Tools

Prism поддерживает механизм инструментов. Агент может самостоятельно принимать решение, когда необходимо вызвать внешний сервис.

Например:

```php
class GetCustomerInfoTool
{
    public function execute(string $customerId): array
    {
        return Customer::find($customerId)->toArray();
    }
}
```

Модель получает описание инструмента и может вызвать его при необходимости.

Фактически это позволяет LLM взаимодействовать с внешним миром.

#### Embeddings

Многие AI-системы используют семантический поиск. Для этого необходимо получать embedding-векторы.

Пример:

```php
$embedding = Prism::embeddings()
    ->using('openai', 'text-embedding-3-small')
    ->fromText($text);
```

Полученный вектор можно сохранить в векторную базу данных и использовать для поиска похожих документов.

### Laravel AI

Репозиторий: [https://github.com/laravel/ai](https://github.com/laravel/ai)

Статус: <mark style="color:green;">**активный**</mark>

Если Prism концентрируется на унификации провайдеров, то Laravel AI стремится интегрировать AI непосредственно в экосистему Laravel.

Идея похожа на то, как Laravel работает с базами данных через Eloquent. Разработчик получает высокоуровневый интерфейс для создания AI-приложений.

#### Работа через фасады

Типичный пример:

```php
use Laravel\AI\Facades\AI;

$response = AI::chat()
    ->model('gpt-5')
    ->prompt('Сделай краткое резюме обращения клиента')
    ->send();
```

Код выглядит естественно для любого Laravel-разработчика.

#### Интеграция с Laravel

Преимущество Laravel AI заключается не столько в работе с моделями, сколько в интеграции со всей экосистемой:

* очередями
* событиями
* контейнером зависимостей
* планировщиком задач
* конфигурацией
* логированием

Например, обработка обращения клиента может выполняться через очередь:

```php
ProcessTicketJob::dispatch($ticket);
```

Внутри задания происходит взаимодействие с моделью.

Это позволяет обрабатывать тысячи запросов без блокировки веб-сервера.

#### AI как часть бизнес-логики

Во многих проектах AI постепенно становится такой же инфраструктурной зависимостью, как база данных или кеш.

Например:

```php
class TicketAnalyzer
{
    public function analyze(string $message): AnalysisResult {
        return AI::chat()
            ->prompt($message)
            ->structured(AnalysisResult::class)
            ->send();
    }
}
```

С точки зрения остального приложения это обычный сервис.

## NeyuronAI

Если Prism можно сравнить с AI-клиентом нового поколения, то NeyuronAI ближе к полноценной платформе для построения агентов.

Его основной фокус – агентные системы и оркестрация.

Другими словами, NeyuronAI помогает строить не отдельные запросы к модели, а целые рабочие процессы.

***

### Агент как объект

Вместо простого вызова модели разработчик описывает агента:

```php
$agent = Agent::make()
    ->name('SupportAgent')
    ->instructions(
        'Ты специалист службы поддержки'
    );
```

После чего агент может выполнять задачи:

```php
$result = $agent->run(
    'Проанализируй письмо клиента'
);
```

***

### Память агента

Одним из ключевых элементов агентных систем является память.

Обычный запрос к модели выглядит так:

```
Запрос → Ответ
```

Агент работает иначе:

```
Запрос
↓
Память
↓
Инструменты
↓
LLM
↓
Результат
```

Агент может помнить предыдущие действия и использовать их в дальнейшем.

Это особенно полезно в чатах поддержки клиентов.

***

### Многоагентные системы

Со временем один агент становится недостаточным.

Появляется специализация.

Например:

```
Coordinator Agent
        |
        +-- Sentiment Agent
        |
        +-- CRM Agent
        |
        +-- Reply Agent
```

Каждый агент отвечает за собственную область ответственности.

Такой подход напоминает организацию работы команды сотрудников.

***

### Оркестрация

Рассмотрим пример обработки обращения клиента.

Шаг 1:

```
Получить письмо
```

Шаг 2:

```
Определить тональность
```

Шаг 3:

```
Получить данные клиента
```

Шаг 4:

```
Сформировать ответ
```

Шаг 5:

```
Передать оператору
```

Подобный процесс называется workflow.

NeyuronAI предоставляет инструменты для описания таких цепочек.

***

### Наблюдаемость

По мере роста количества агентов возникает новая проблема.

Необходимо понимать:

* какой агент был вызван;
* какой инструмент использовался;
* сколько токенов было потрачено;
* сколько времени заняла операция;
* почему агент принял конкретное решение.

Это область observability.

Без нее эксплуатация сложных агентных систем становится крайне затруднительной.

***

## Что выбрать

У каждой библиотеки есть собственная область применения.

Prism хорошо подходит для:

* универсального доступа к моделям;
* работы с несколькими провайдерами;
* structured output;
* embeddings;
* tool calling.

Laravel AI подойдет для:

* Laravel-проектов;
* тесной интеграции с экосистемой фреймворка;
* быстрого внедрения AI-функциональности.

NeyuronAI ориентирован на:

* AI-агентов;
* workflows;
* память;
* оркестрацию;
* многоагентные системы.

На практике эти решения не всегда являются конкурентами. Во многих проектах они могут использоваться совместно.

Например, Laravel AI может выступать точкой интеграции с приложением, Prism – обеспечивать работу с моделями, а NeyuronAI – управлять агентами и их взаимодействием.

## Итоги

Экосистема PHP для работы с ИИ развивается значительно быстрее, чем многие ожидали еще несколько лет назад. Если раньше разработчик был вынужден вручную вызывать API моделей и самостоятельно строить всю инфраструктуру вокруг них, то сегодня появились инструменты гораздо более высокого уровня.

Prism упрощает работу с провайдерами моделей и структурированным выводом. Laravel AI делает ИИ естественной частью Laravel-приложения. NeyuronAI предоставляет фундамент для построения полноценных агентных систем.

Для большинства современных AI-приложений путь развития выглядит примерно так:

```
HTTP API
    ↓
AI Client
    ↓
Tools
    ↓
Structured Output
    ↓
Workflows
    ↓
Agents
    ↓
Multi-Agent Systems
```

Именно в направлении агентных систем сегодня движется большая часть индустрии. Поэтому понимание возможностей экосистемы PHP становится важным навыком для любого бэкенд-инженера, который планирует создавать AI-продукты следующего поколения.
