# Глоссарий

Эта глава служит опорной точкой. Сюда можно возвращаться, если термин встречается в коде, формуле или описании алгоритма и хочется быстро освежить смысл без погружения в теорию.

### Attention

Attention – это механизм transformer-моделей, позволяющий AI определять, какие части входного текста наиболее важны для текущего токена.

Вместо обработки текста строго по порядку модель анализирует связи между всеми токенами контекста одновременно.

Основой attention является вычисление “внимания” между токенами:

$$
Attention(Q,K,V)=softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

Механизм attention позволяет LLM:

* учитывать длинный контекст
* лучше понимать связи между словами
* выполнять reasoning
* работать с context window

Именно attention стал ключевой идеей архитектуры трансформеров и фундаментом современных LLM.

### Batching

Batching (пакетная обработка) – это техника обработки нескольких запросов одновременно в рамках одного вычисления.

В AI-системах batching часто используется во время вывода для повышения производительности GPU и снижения стоимости обработки запросов.

Вместо последовательной обработки:

* request 1
* request 2
* request 3

система объединяет их в один batch (пакет) и выполняет параллельно.

Производительность batching можно упрощённо представить так:

$$
Throughput \propto Batch\ Size
$$

Чем больше размер пакета, тем выше пропускная способность системы, однако слишком большие пакеты могут увеличивать латентность.

Batching особенно важен для для распределенного вывода, AI API и high-load AI-платформ.

### Context window

Context window (контекстное окно) – это объём информации, который модель может "удерживать в памяти" во время одного inference-запроса.

Обычно context window измеряется в токенах. В него входят:

* сообщение пользователя
* system prompt
* предыдущие сообщения
* документы
* результаты tool calling
* промежуточные reasoning-шаги

Если данные превышают размер context window, модель начинает "забывать" часть информации или теряет важный контекст.

Упрощённо context window можно представить как ограниченную область памяти:

$$
C = \sum_{i=1}^{n} t_i
$$

где:

* $$C$$ – общий размер контекста;
* $$t_i$$ – отдельные токены.

Размер context window напрямую влияет на:

* качество reasoning
* способность работать с длинными документами
* memory AI-агента
* качество multi-step planning

Современные LLM могут поддерживать контекстные окна от нескольких тысяч до миллионов токенов, однако увеличение контекста обычно требует больше вычислительных ресурсов и повышает стоимость инференса.

### Distributed platform

Distributed platform (распределенные платформы) – это распределённая платформа, в которой вычисления, хранение данных и выполнение сервисов происходят не на одном сервере, а на множестве узлов, работающих совместно.

В AI-системах distributed platform используется для:

* масштабирования AI-агентов
* распределения нагрузки
* обработки больших объёмов данных
* отказоустойчивости
* параллельного выполнения задач

Типичная distributed platform включает:

* очереди сообщений
* сервисы и микросервисы
* распределённые базы данных
* orchestration layer
* worker-ноды
* memory и caching systems

Во многих AI-agent системах reasoning, tool calling и memory могут выполняться на разных узлах одновременно.

Производительность распределённой системы часто растёт вместе с количеством вычислительных узлов:

$$
P \approx n \cdot p
$$

где:

* P – общая производительность
* n – количество узлов
* p – производительность одного узла

На практике distributed platform является фундаментом для современных AI-продуктов, облачных сервисов и multi-agent систем.

### Inference

Inference (инференс – вывод) – это процесс использования уже обученной модели для получения ответа на новый запрос. Проще говоря, это этап “применения знаний”, в отличие от обучения (training).

В контексте AI-агентов inference – это момент, когда модель:

* получает input (запрос, контекст, данные)
* обрабатывает его через нейросеть
* генерирует output (ответ, план, действие)

В reasoning system inference обычно происходит многократно, а не один раз: модель может вызывать себя итеративно на каждом шаге планирования.

Важно различать:

* training – обучение модели на данных;
* inference – использование модели в реальном времени.

С точки зрения вычислений inference можно представить как функцию:

$$
y = f_\theta(x)
$$

где:

* $$x$$ – входной запрос
* $$y$$ – результат
* $$\theta$$ – фиксированные параметры модели после обучения.

В AI-системах inference часто оптимизируют отдельно, потому что именно он влияет на:

* задержку ответа (latency)
* стоимость запроса
* масштабируемость системы

В распределенных платформах inference может выполняться на разных узлах (CPU/GPU/edge), что позволяет обрабатывать большое количество запросов параллельно и снижать нагрузку на систему.

### Latency

Latency – это задержка между отправкой запроса и получением ответа от системы.

В AI-системах latency включает:

* сетевую задержку
* время inference
* работу tools и API
* ожидание в очередях

Упрощённо общую задержку можно представить так:

$$
L = L_{network} + L_{inference} + L_{tools}
$$

Высокая latency ухудшает пользовательский опыт и замедляет работу AI-агентов, особенно при сложном рассуждении и многоэтапном исполнении.

### Observability

Observability – это способность системы предоставлять достаточно информации о своём внутреннем состоянии для анализа, мониторинга и диагностики проблем.

В AI-agent системах observability особенно важен, потому что reasoning, tool calling, memory и inference часто распределены между множеством компонентов.

Обычно observability включает:

* logs
* metrics
* traces
* event tracking
* monitoring inference и latency
* анализ reasoning chains
* audit и debugging AI-решений

В распределённых системах observability помогает понимать:

* почему агент принял конкретное решение
* где возникла ошибка
* какой tool был вызван
* сколько занял inference
* какой компонент стал bottleneck.

Типичная модель observability строится вокруг трёх основных источников данных:

$$
O = Logs + Metrics + Traces
$$

где:

* Logs – события и сообщения системы;
* Metrics – численные показатели;
* Traces – цепочки выполнения запросов между сервисами.

Без observability сложные AI-системы становятся практически "чёрным ящиком", который трудно масштабировать, отлаживать и поддерживать.

### Probabilistic system

Probabilistic system (вероятностные системы) – это система, принимающая решения не по жёстким правилам, а на основе вероятностей.

Большинство современных AI-моделей являются вероятностными системами: они не "знают" правильный ответ заранее, а вычисляют наиболее вероятный следующий токен, действие или решение.

В LLM каждое следующее слово выбирается на основе распределения вероятностей:

$$
P(w_t \mid w_{1:t-1})
$$

где:

* $$w_t$$ – следующий токен;
* $$w_{1:t-1}$$ – предыдущий контекст.

Именно поэтому AI может:

* генерировать разные ответы на один и тот же запрос
* ошибаться
* проявлять неопределённость
* использовать сэмплинг и температуру

В ИИ-агенте измерено вероятностное поведение особенно заметно в рассуждениях, планировании и автономном принятии решений.

В отличие от детерминированных систем, где одинаковый input всегда даёт одинаковый output, вероятностные системы работают с вероятностными оценками и допускают вариативность поведения.

### Reasoning system

Reasoning system (система рассуждений) – это система рассуждения AI-агента, отвечающая за анализ задачи, планирование шагов и принятие решений.

Если LLM генерирует текст, то reasoning system определяет, как именно модель "думает" перед ответом.

Обычно reasoning system включает:

* декомпозицию задачи
* построение логической цепочки
* выбор инструментов
* проверку промежуточных результатов
* работу с памятью и контекстом

Например, запрос:&#x20;

"Найди лучший маршрут поездки"

может быть разбит на несколько шагов:

1. Анализ параметров поездки
2. Поиск вариантов
3. Сравнение маршрутов
4. Выбор оптимального решения

Идея reasoning часто описывается как разбиение сложной задачи на подзадачи:

$$
T = \sum_{i=1}^{n} s_i
$$

где $$T$$ – итоговая задача, а $$s_i$$ – отдельные шаги рассуждения.

Именно reasoning system делает AI-агента более автономным, способным планировать действия и исправлять ошибки.

### Transformer

Transformer (трансформер) – это архитектура нейронных сетей, ставшая основой современных LLM и большинства генеративных AI-систем.

Главная идея transformer-модели заключается в использовании механизма attention, который позволяет модели анализировать взаимосвязи между всеми токенами входного текста одновременно, а не последовательно.

До появления transformer многие модели обрабатывали текст по порядку, слово за словом. Transformer позволяет модели видеть весь контекст сразу, что значительно улучшило качество понимания языка.

Ключевым элементом архитектуры является self-attention:

$$
Attention(Q,K,V)=softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

где:

* $$Q$$ – Query
* $$K$$ – Key
* $$V$$ – Value
* $$d_k$$ – размерность вектора

Механизм attention помогает модели определять, какие части текста наиболее важны для текущего токена.

Архитектура transformer обычно включает:

* embeddings
* positional encoding
* multi-head attention
* feed-forward layers
* residual connections
* normalization layers

Именно transformer стал фундаментом для таких моделей, как OpenAI GPT, Google Gemini, Meta Llama и многих современных AI-agent систем.
