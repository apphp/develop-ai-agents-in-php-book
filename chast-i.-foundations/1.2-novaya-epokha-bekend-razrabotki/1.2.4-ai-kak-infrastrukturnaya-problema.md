# 1.2.4 AI как инфраструктурная проблема

На раннем этапе многим казалось, что интеграция AI – это просто подключение OpenAI API.

Но на практике production AI-системы очень быстро превращаются в полноценную инфраструктурную задачу.

Почти сразу появляются новые сложности:

* задержки при ответах (latency)
* повторные запросы при ошибках (retries)
* контроль стоимости токенов
* переключение между AI-провайдерами при сбоях
* управление контекстом
* версионирование промптов
* мониторинг и observability

Кроме этого, системе нужно хранить эмбеддинги, индексировать данные для семантического поиска и строить пайплайны для оценки качества моделей.

Сегодня типичная архитектура продуктовой AI-платформы обычно выглядит так:

```
Client
  ↓
API Gateway
  ↓
AI Orchestrator
  ↓
Prompt Pipeline
  ↓
LLM Provider Layer
  ↓
Tools / Memory / RAG
```

Главным элементом всей системы постепенно становится уровень оркестровки.

Именно он управляет взаимодействием между моделями, промптами, памятью, инструментами и внешними сервисами. По сути, уровень оркестровки превращается в центральный координационный механизм всей AI-платформы.
