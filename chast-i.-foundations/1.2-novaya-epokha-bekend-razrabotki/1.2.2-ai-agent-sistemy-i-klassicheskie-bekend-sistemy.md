# 1.2.2 AI-agent системы и классические бэкенд-системы

Классическая бэкенд-система обычно представляет собой набор заранее определенных сервисов. Архитектура таких систем довольно жесткая: API Gateway вызывает нужный сервис, сервис обращается к базе данных, затем возвращает результат.

Все маршруты известны заранее.

AI-agent системы работают иначе. Агенту можно дать высокоуровневую задачу, а детали выполнения он сможет динамически определить внутри ограничений слоя оркестрации.

Представим запрос:

> "Найди лучшие ноутбуки для ML до $2500 и сравни их."

Для классического бэкенда такая задача обычно требует большого количества заранее описанных правил, эвристики и логики поиска. Что означает "лучшие"? Какие характеристики важны для ML? Как сравнивать устройства?

AI-agent пайплайн способен самостоятельно разбить задачу на этапы. Сначала определить намерение пользователя, затем выполнить поиск, извлечь характеристики устройств, провести рассуждение и только после этого сгенерировать итоговую рекомендацию.

```
Intent Detection
    ↓
Web Search
    ↓
Data Extraction
    ↓
Reasoning
    ↓
Generated Recommendation
```

Такой backend уже нельзя назвать обычной CRUD-системой. Это уже система рассуждений ([reasoning system](../../vvedenie/glossarii.md#reasoning-system)).
