# 1.4.3 Tool calling architecture

## 1.4.3 Tool calling architecture

Современные LLM редко работают изолированно.

Настоящая сила появляется, когда модель может использовать инструменты.

Это называется tool calling.

***

### Базовая идея

LLM не выполняет действия напрямую.

Она лишь генерирует structured intent.

Например:

```json
{
  "tool": "search_web",
  "arguments": {
    "query": "latest NVIDIA earnings"
  }
}
```

Orchestrator получает это сообщение и уже сам вызывает реальный tool.

### Типичный execution flow

1. User message
2. LLM decides tool
3. Backend validates arguments
4. Tool execution
5. Result normalization
6. Result returned to LLM
7. Final response generation

***

### Почему orchestration нельзя доверять модели

Модель probabilistic.

Она может:

– hallucinate tool names\
– генерировать invalid JSON\
– путать schema\
– вызывать неправильный tool

Поэтому orchestration почти всегда deterministic.

***

### Пример tool calling на PHP

```php
<?php

$response = [
    "tool" => "weather_api",
    "arguments" => [
        "city" => "Jerusalem"
    ]
];

if ($response["tool"] === "weather_api") {

    $city = $response["arguments"]["city"];

    $weather = getWeather($city);

    echo json_encode([
        "result" => $weather
    ]);
}

function getWeather(string $city): array
{
    return [
        "temperature" => 28,
        "condition" => "Sunny"
    ];
}
```

***

### Structured outputs

Почти все современные AI systems используют structured outputs:

– JSON schema\
– function calling\
– typed outputs\
– validation layers

Потому что free-form text плохо подходит для orchestration.
